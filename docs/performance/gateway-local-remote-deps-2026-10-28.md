## 依赖故障与环境边界

测量期间两个 SSH 隧道均发生 Connection reset。JWT 第一轮 128 并发 P99 约 4.22s、第二轮单并发约 4.20s，日志确认撤销开关与黑名单 Redis 查询超时后放行。HTTP 200 不等于撤销检查成功。这些异常数据保留在原始 results.json 中；上表 JWT 使用恢复隧道后独立补测的六轮结果，且各轮均检查没有新增撤销查询失败。该测试只使用固定有效 JWT，验证缓存/撤销本地缓存较热，不代表唯一 Token 冷验证能力。

错误追踪上报出现 HTTP 400，管理端错误为 LinkedHashMap 无法强转 String，属于追踪数据类型兼容问题，需要单独修复。

主机 AMD Ryzen 5 5600H（6 核 12 线程），约 15.4 GiB 内存。采样期间可用物理内存最低 147 MiB，网关工作集峰值 870 MiB、私有内存峰值 973 MiB。采样器启动前另一次系统查询仅约 494 MiB 可用。观察到明显内存压力和同机负载波动；CPU/事件循环标记不能覆盖全部系统换页影响，未标记轮次也不能视为独立压力机数据。

已测到普通转发、重复凭证认证与流式透传可正常工作，但当前主要风险是追踪写入链路的背压、远程依赖/SSH 连接稳定性以及大请求体在高并发时的尾延迟。这次 60 秒稳态检查不是长期耐久测试，不能据此排除内存泄漏。没有验证真实业务上游、TLS、唯一 Token、大量不同 Basic 凭证、WAF、分布式限流和故障恢复的安全语义。
